# Chapter 7: 职场语言与管理沟通

## Core Idea
职场沟通的关键不在"会说话"，在"用对工具"——邮件 / IM / 会议 / 报告 / 谈判 5 大场景各有规则。

## Frameworks Introduced

### 1. 职场沟通 4 场景
- **单向表达**（汇报、通知、邮件）：目的明确 → 信息完整 → 结论清晰
- **多向沟通**（会议、谈判、跨部门协调）：议程明确 → 时间盒 → 共识机制
- **即时沟通**（IM、电话）：5 分钟决策 → 微信预告 → 留记录
- **正式沟通**（合同、公告、政策）：格式规范 → 法务 review → 留档
- **Use when**: 接到任何沟通任务的 30 秒内选择

### 2. 邮件结构（5 段式）
1. **主题**（一行）：动词 + 对象 + 时间——如"[汇报]本周进度报告（2026-W38）"
2. **问候**：1 行礼貌问候
3. **正文**：3 段以内——背景 / 内容 / 下一步
4. **附件**：列清楚文件 + 大小
5. **署名**：姓名 + 职位 + 联系方式
- **Use when**: 任何职场邮件

### 3. 职场汇报 PREP（升级版，源自 §5.1 + §7.1）
- **P（Point）**：结论先行
- **R（Reason）**：关键依据（数据 / 事实）
- **E（Example）**：1 个具体案例
- **P（Point）**：重申结论 + 行动项（谁 / 何时 / 做什么）
- **Use when**: 任何向上汇报（口头 + 邮件都适用）

### 4. 会议主持 6 动作（出自 §7.2，扩展自 §5.2）
- **开 场**：目的 + 议程 + 时长
- **引 导**：先点不主动的人 → 再点主动的人
- **聚 焦**：离题时拉回
- **总 结**：每段结束总结
- **共 识**：让每个人复述
- **收 束**：结论 / 行动 / 责任人 / 时限
- **Use when**: 主持 5+ 人会议

### 5. 跨部门沟通 4 原则
- **共同目标**：从部门利益上升到公司利益
- **数据说话**：避免主观判断
- **机制保障**：约定会议 / 周报 / 复盘频率
- **找决策者**：如果对方不能拍板，让 TA 找能拍板的
- **Use when**: 推动需要多部门协作的项目

### 6. 谈判 4 阶段
1. **准备**：列利益清单 / BATNA / 底线
2. **开局**：建立信任 + 摸底
3. **博弈**：用利益交换 + 找共同点
4. **收局**：达成共识 + 备忘
- **Use when**: 商务谈判 / 跨公司合作 / 跨部门资源协调

### 7. 职场向上沟通 3 原则
- **结论先行**：不要绕
- **带方案**：不要只抛问题，要给 A/B/C 方案 + 推荐
- **同步进度**：主动 sync，不要等到老板来问
- **Use when**: 任何向上汇报 / 跨级沟通

## Key Concepts
- **BATNA**：Best Alternative to a Negotiated Agreement——谈判破裂时的最佳替代方案
- **跨部门沟通**：找到共同目标，把"我们 vs 他们"变成"我们 vs 问题"
- **向上管理**：让老板的工作更容易——主动同步进度 + 带方案
- **向下沟通**：让下属工作清晰——明确目标 + 复盘机制
- **平行沟通**：让同事愿意配合——找共同利益
- **决策者**：能拍板的人——找不到决策者就找不到答案

## Mental Models

### 邮件 5 段式（§7.1）
| 段 | 时长 | 作用 |
|---|---|---|
| 主题 | 1 行 | 让对方 10 秒内知道"这是什么 + 要做什么" |
| 问候 | 1 行 | 礼貌 |
| 正文 | 3 段 | 背景 / 内容 / 下一步 |
| 附件 | 列表 | 让对方快速打开 |
| 署名 | 1 行 | 让对方知道你是谁、怎么联系 |

**Use when**: 写任何职场邮件——尤其是 5 分钟内要回的那种

### 跨部门沟通"电梯演讲"模板（§7.2）
**30 秒让对方听明白并想配合**：
- "我们正在做 [项目]，目标 [共同目标]"
- "需要 [对方部门] 提供 [具体支持]"
- "如果不配合会 [风险 / 损失]"
- "配合的回报是 [对方利益]"

**Use when**: 在电梯里遇到对方部门负责人，争取支持

## Anti-patterns
- **汇报无结论**："做了 ABC" → "**最重要的是 X**，原因是 Y"
- **抛问题不给方案**："老板，X 卡住了" → "X 卡住了，原因是 Y，方案 A/B/C，我推荐 A"
- **会议不写纪要** → 24 小时内发
- **邮件主题空泛**："汇报" → "[汇报]本周进度 W38，含两个 blocker"
- **跨部门无共同目标** → 找到"我们"vs"问题"
- **找错人决策**：对方说"我回去请示一下" → 问"请示谁，能直接拉群吗？"
- **频繁用 IM 推重大事** → 改邮件 / 当面沟通

## Worked Example — 向上汇报邮件模板（出自 §7.1）

```
主题: [周报] 第 38 周（9.15-9.21）项目进度：X 已完成，Y 仍 blocker

张总：

本周 X 功能已上线，下周一全量发布；Y 功能遇到 1 个 blocker（见下）。
已与对方团队对齐，预计下周三解决。

1. 本周完成
   - X 功能上线（部署时间：周三 14:00，无回滚）
   - 与运营团队对齐发布节奏
   - 团队周会完成 review（详见附件周报）

2. 下周计划
   - 全量发布 X（含灰度监控）
   - 解决 Y blocker（责任人：王××；预计周三前）

3. Blocker
   - Y 卡点：第三方 API 限流（已联系对方技术，明天拉群对齐）
   - 风险：若周三仍未解决，Y 上线推迟到下周五

4. 需要您支持
   - 与第三方负责人打个招呼，加速对齐（已与对方一线团队对齐，但对方 PM 权限不够）

附件：
- 详细周报：w38-report.pdf（200 KB）
- 部署记录：deploy-log-20260917.txt（5 KB）

如有疑问，随时电话沟通。

王××
前端工程师 / 产品组
电话：138-xxxx-xxxx
```

**关键 takeaway**：
- 主题：动词 + 对象 + 时间 + 状态——10 秒可读
- 第 1 段：最重要的事 1 句话（已完成 / blocker）
- 第 2-3 段：本周 / 下周 / blocker / 需要支持——结构清晰
- 附件：用数字标注大小
- 署名：职位 + 联系方式
