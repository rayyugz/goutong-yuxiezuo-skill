# Chapter 5: 集体交流与沟通效果

## Core Idea
集体交流的难点不是"自己说清楚"，而是"让多人达成共识"——汇报、会议、共识这 3 件事的共同核心是"5 要素 + 双向反馈"。

## Frameworks Introduced

### 1. 汇报工作 4 类型
- **口头汇报**：即时性强、有来有往（适合紧急或重要决策）
- **书面汇报**：可追溯、可复制（适合周期性 / 流程性事项）
- **PPT 汇报**：视觉化、可多人同时看（适合复杂项目）
- **混合汇报**：先发书面 + 现场口头 + PPT 重点（适合重要决策）
- **Use when**: 接到"汇报一下"的 30 秒内选择类型

### 2. 汇报结构 PREP（A 升级版，源自 §5.1）
- **Point（结论先行）**：30 秒内说出结论
- **Reason（依据）**：为什么是这样——1-2 个数据 / 事实
- **Example（例证）**：1 个具体案例
- **Point（重申结论）**：再次强调
- **Use when**: 任何口头汇报（5 分钟以内）

### 3. 会议组织 5 阶段
1. **会前**：明确目的 + 邀请相关人 + 准备议程 + 发通知
2. **开场**：5 分钟内说明会议目的、时长、议程
3. **主体**：按议程推进，每人限时，控制离题
4. **收束**：明确结论 + 待办 + 责任人 + 时间
5. **会后**：发会议纪要 + 跟进待办
- **Use when**: 组织任何 5 人以上的会议

### 4. 会议主持 6 动作（出自 §5.2）
- **开场白**：欢迎 + 议程 + 时长
- **时间控制**：每个议程项计时，超时打断
- **引导发言**：先点不主动的人 → 再点主动的人
- **聚焦议题**：离题时拉回（"这是个重要话题，我们可以下次专门讨论"）
- **总结每段**：每段结束时总结"刚才我们说到了 X / 决定 Y"
- **收束会议**：明确结论 / 行动 / 责任人 / 时限
- **Use when**: 主持任何会议

### 5. "沟而不通"5 原因（出自 §5.3，作者原创）
1. **对象不清**：不知道对方是谁、需要什么
2. **时间不当**：在不合适的时间打扰
3. **内容不明**：自己也没想清楚要说什么
4. **目的不明**：不知道要对方做什么
5. **效果不评**：不知道对方是否理解
- **Use when**: 沟通失败后做根因分析

### 6. 达成共识 5 步
1. **倾听**：先听完所有人的意见
2. **提炼**：找出共同点
3. **妥协**：识别分歧点 → 找最大公约数
4. **推动**：用事实 / 数据 / 先例推动
5. **确认**：让每个人复述一次共识
- **Use when**: 推动会议 / 谈判 / 跨部门协调

### 7. 沟通的 5 要素（再次强调）
沟通者 · 信息 · 目的 · 环境 · 工具 —— 在集体场景下每个要素的复杂度都升级
- **Use when**: 集体沟通前 checklist

## Key Concepts
- **会议纪要**：会后发，列结论、待办、责任人、时间——这是会议的"产出"
- **沟而不通**：自以为沟通过，对方没动 / 没懂
- **PREP**：Point-Reason-Example-Point 的口头汇报结构
- **共识**：不是"全员同意"，而是"全员接受"——这是推动力的关键
- **议程**：会议的结构化安排——避免"开了 3 小时没结论"

## Mental Models

### PREP（§5.1）
- **Point**：先说结论（不要绕）
- **Reason**：1-2 个数据 / 事实
- **Example**：1 个案例
- **Point**：再强调结论
- **Use when**: 5 分钟以内口头汇报——尤其是"老板临时问进展"

### "沟而不通"5 原因诊断（§5.3）
| 现象 | 对应原因 | 修复方法 |
|---|---|---|
| 对方没听懂 | 内容不明 | 重新组织语言 + 举例 |
| 对方没行动 | 目的不明 | 明确"请你做什么" |
| 对方抗拒 | 对象不清 | 调整话术匹配对方身份 |
| 对方被打扰 | 时间不当 | 选合适时机 |
| 事后没回音 | 效果不评 | 跟进确认 + 让对方复述 |

## Anti-patterns
- **汇报无结论**："说一下最近的工作" → "做了 ABC，预计下周完成 DEFG，**最重要的进展是 X**"
- **会议无议程**：与会者不知道来干嘛 → 会前发议程
- **会议不计时**：议程一项就用了整场 → 设时间盒
- **主持人包场**：一个人讲 80% → 引导他人发言
- **离题不拉回**：3 个议题混成 1 个 → 明确"下次专门讨论"
- **会后无纪要**：3 天后没人记得结论 → 24 小时内发纪要
- **达成共识没确认**：每个人理解的不一样 → 让每个人复述

## Worked Example — 会议纪要模板（出自 §5.2 知识串讲）

```
会议纪要
————————————————————————————

会议名称：××项目进度同步会
时间：2026-09-20 14:00-15:00
地点：3 楼会议室
主持人：王××
参会人：王××（主持人）、李××、张××、赵××、刘××（记录）

【议程 & 结论】

议程 1：上周工作完成情况（15 分钟）
- 结论：完成 API 设计，进入开发阶段；李××负责的前端组件延期到本周三
- 风险：周三仍完不成会影响下游张××

议程 2：本周计划（15 分钟）
- 结论：本周目标——完成开发 + 第一轮自测
- 责任人：王××（API）、李××（前端）、张××（联调）

议程 3：阻塞项（15 分钟）
- 阻塞 1：测试环境不稳定（赵××）
  - 解法：赵××周三前出修复方案；李××协助验证
- 阻塞 2：UI 设计稿延期（设计组）
  - 解法：王××今天跟设计组沟通，要下周一前完成

议程 4：下次会议
- 时间：2026-09-27 14:00
- 议程：联调进度 + 测试环境稳定性

【行动项跟进】

| 事项 | 责任人 | 截止时间 |
|---|---|---|
| 前端组件完成 | 李×× | 2026-09-23 |
| 测试环境修复 | 赵×× | 2026-09-23 |
| UI 设计稿 | 设计组 | 2026-09-28 |
| API 开发完成 | 王×× | 2026-09-25 |
```

**关键 takeaway**：
- 主持人 + 记录人分离（不能同一个人）
- 每项议程必须有结论（哪怕是"未达成共识，下次继续"）
- 行动项必须 4 个 W（What / Who / When / Where）
- 24 小时内发纪要，48 小时内所有人确认
